# 家計簿アプリ 実装指示書

## 1. 目的と役割分担

個人用の家計簿PWAと、Claudeから操作するためのMCPサーバーを作る。

| 担当 | 責務 |
|---|---|
| このアプリ | 月ごとの収支管理、固定費、支払い予定 |
| マネーフォワード ME | 資産残高と資産の管理 |
| 分析用チャット | CSVの確認と取り込み、収支の分析、資産形成の相談 |

利用者は開発者本人のみ。主な利用環境はiPhoneのSafari、開発環境はWindows。

## 2. 技術構成

- 画面: React、TypeScript、Vite、PWA
- 配信: GitHub Pages
- DB: Supabase（PostgreSQL）。Workout Trackerとは別プロジェクト
- 認証: Supabase Auth。本人のアカウント作成後は新規登録を無効化
- MCP: Supabase Edge Function、OAuth（DCR）
- 定期処理: pg_cron
- テスト: Vitest、Playwright

MCPサーバーの構成と認証は、Workout Trackerの実装（`../training_recorder`）を参照する。ただしSupabaseプロジェクト、コネクタ、シークレットは共有しない。

## 3. 確定した機能要件

### 3.1 入力
- 種別: 支出、収入、振替/投資
- 項目: 金額、日付、費目、支払方法、メモ（任意）
- 必須: 金額、費目
- 支払方法: 支出は現金、カード、QR、口座。収入は口座、現金。振替/投資は口座、カード、現金
- 登録後は金額、費目、メモを空にする
- 最近の明細5件を表示し、タップで編集と削除ができる

### 3.2 固定費
- 項目: 名前、金額、費目、周期（毎月、毎年）、支払月（毎年のみ）、支払日（1〜28日、月末）、支払方法、開始月、終了月（任意）、金額が毎回変わる、自動記録
- 一覧に月額合計と年額合計を表示する。年払いは12で割って月額合計に含める
- 自動記録がオンなら、支払日に明細を作る
- 金額が毎回変わるものは見込み額で記録し、確定後に修正する
- 登録日より前の支払日は、自動記録も予定表示も行わない
- 「サブスクとして管理」のスイッチを持つ（`is_subscription`）。固定費の入力画面で切り替える

### 3.2.1 サブスク
目的は、サブスクにいくら使っているかを把握すること。

- 下タブに「サブスク」画面を追加する。`is_subscription` が立った固定費を一覧にする
- 追加の項目は持たない。名前、金額、周期、支払方法、開始月、終了月は固定費のものをそのまま使う
- 画面の上部に次の4つを表示する
  - 月額換算の合計（年払いは12で割る）
  - 年額換算の合計（月払いは12倍する）
  - 今年の実際の支払額（記録済みの明細の合計）
  - 契約開始からの累計額（記録済みの明細の合計）
- 終了月が過ぎたものは「解約済み」として別枠に分ける。月額と年額の合計には含めず、累計額には含める
- 編集は固定費画面と同じフォームで行う。サブスク画面からも同じフォームを開く
- カレンダーの予定と明細は、固定費として登録されているため追加の実装なしで連動する。明細は `fixed_cost_id` で固定費とひもづく
- 解約したものは、固定費を削除せず終了月を入れる。削除すると明細のひもづけが外れ、累計額から消える

### 3.3 カレンダー
- 月の移動ができる
- 月の支払いは「支出の明細 + 未記録の固定費」で計算する
- 支払い済み、これからの予定、収入を表示する
- 日ごとの支払い額と収入を表示し、タップで内訳を表示する
- 内訳の明細は入力画面、固定費は固定費画面で編集する
- 振替/投資は月の支払いに含めず、日の内訳には表示する

### 3.4 費目
- 種類: 支出、収入、振替/投資、固定費
- 追加、名前変更、並び替え、削除ができる
- 使用中の費目は `is_hidden` を立てて選択肢から外し、過去の記録には名前を残す
- 同じ種類で同じ名前の費目は登録できない

### 3.5 MCP
読み書きの範囲は明細、固定費、費目、月の予定、収支集計。

| ツール | 内容 |
|---|---|
| `log_transaction` | 明細を1件登録 |
| `list_transactions` | 期間、種別、費目で検索 |
| `update_transaction` | 見込み額の確定を含む更新 |
| `delete_transaction` | 明細を削除 |
| `import_transactions` | CSV由来の明細を一括登録。既定は `dry_run: true` |
| `list_fixed_costs` | 固定費の一覧 |
| `save_fixed_cost` | 固定費の追加、更新（`is_subscription` を含む） |
| `get_subscription_summary` | サブスクの一覧と、月額換算、年額換算、今年の支払額、累計額 |
| `delete_fixed_cost` | 固定費の削除 |
| `list_categories` | 費目の一覧 |
| `save_category` | 費目の追加、更新、非表示 |
| `get_month_schedule` | 月の未記録の固定費 |
| `get_cashflow_summary` | 月別の収入、支出、固定費、振替/投資、収支、貯蓄率 |

- ユーザーのアクセストークンでDBへ接続し、RLSを必ず通す。service roleキーをMCPのデータ操作に使わない
- 削除系ツールには破壊的操作の注釈を付ける
- 結果の金額は円の整数で返す

### 3.6 マネーフォワード MEのCSV
アプリにCSV画面は作らない。分析用チャットがCSVを読み、MCPへ渡す。

`import_transactions` の流れ:
1. `dry_run: true` で、新規、重複、固定費との一致候補を返す
2. 本人が確認する
3. `dry_run: false` で書き込む

- `source = 'moneyforward'`、`external_id = CSVの明細ID` として重複を防ぐ
- 固定費の見込み明細と一致した行は、新規登録せず見込み明細を更新する
- PayPay引き落としなど取り込まない行は、分析用チャットで指示して除外する。アプリやMCPに個別の除外ルールを固定で持たせない
- CSVの列名と振替の扱いは、Step 5で実際のCSVを確認してから確定する

### 3.7 初期版に含めないもの
資産残高の記録、予算管理、グラフ、明細検索、アプリ上のCSV取り込み、レシート画像の保存。

## 4. データ設計

`supabase/migrations/` のSQLを正とする。

- `20261103000000_init.sql`: テーブル、RLS、初期費目、固定費展開、自動記録、予定、収支集計
- `20261103000100_fixed_cost_cron.sql`: 毎日00:05 JSTの自動記録ジョブ
- `20261108000000_subscriptions.sql`: 固定費の `is_subscription` 列とサブスク集計 `get_subscription_summary`

主な判断:
- 金額は正の整数、方向は `type` で持つ
- `recorded_through` により、削除した自動記録は再作成せず、Supabaseの一時停止後は追いつき記録する
- `post_fixed_costs` は認証済みユーザーから実行できない
- 貯蓄率は `(収入 - 支出) / 収入`。振替/投資は支出に含めない

## 5. 画面

`docs/mock/Main.dc.html` が全画面の見本。下タブは入力、カレンダー、固定費の3つ。サブスク画面を加えて4つにする。サブスク画面はモックにないため、固定費画面の見た目を踏襲する。

- ダークテーマ、Noto Sans JP
- タップ領域は44px以上
- 配色の基本は `#14161A`（背景）、`#1E2126`（面）、`#FFB27A`（支出）、`#8CC8FF`（収入）、`#C9CED6`（振替/投資）

モックのサンプルデータとアプリ内の状態管理は本番へ流用しない。

## 6. 実装手順

### Step 0: 開始前の確認
本人の作業が必要なもの:
- Supabaseの新規プロジェクト作成
- GitHubリポジトリの作成とPages設定
- `.env.local` への接続情報の設定

シークレットを `.env.example` 以外に書かない。`.env*` はコミットしない。

**完了条件:** `supabase link` でプロジェクトへ接続できる。

### Step 1: DB
1. マイグレーションを適用する
2. `pg_cron` のジョブ登録を確認する
3. Supabaseの生成機能でDB型を作る

**完了条件:** RLSが3テーブルすべてで有効。匿名キーで全テーブルが読めない。

### Step 2: PWA基盤
1. Vite、React、TypeScript、PWA、Supabaseクライアントを設定する
2. ログインと、初回の `seed_default_categories()` 実行を実装する
3. GitHub Pagesへの配信を設定する

**完了条件:** iPhoneでログインでき、ホーム画面に追加できる。

### Step 3: 画面
入力、費目、固定費、サブスク、カレンダーの順に実装する。サブスクの着手前に `20261108000000_subscriptions.sql` を適用し、DB型を再生成する。カレンダーは `transactions` と `get_month_schedule` を組み合わせる。

**完了条件:** 3章の機能が実DBで動く。

### Step 4: MCP
1. OAuth（DCR）付きのEdge Functionを作る
2. CSV以外の12ツールを実装する
3. Claudeへカスタムコネクタとして接続する

**完了条件:** チャットから明細の登録、更新、削除、月の予定と収支の取得ができる。

### Step 5: CSV取り込み
1. 実際のMEのCSVで列名、明細ID、振替の表現を確認する
2. 確認結果を本書へ追記する
3. `import_transactions` を実装する

**完了条件:** 同じCSVを2回取り込んでも増えない。固定費の見込み明細が重複しない。

## 7. テスト観点

| 区分 | 観点 |
|---|---|
| 入力 | 必須チェック、3種別の費目と支払方法の切り替え、編集、削除 |
| 固定費 | 毎月、毎年、月末、2月末、開始月、終了月、登録日より前の支払日 |
| 自動記録 | 同日再実行、削除後の非再作成、停止後の追いつき、手動記録の未記録表示 |
| サブスク | 月額換算と年額換算の合計、今年と累計の支払額、解約済みの分離、固定費の削除で累計から消えること |
| カレンダー | 実績と予定の合計、振替/投資の除外、月初の曜日、月移動 |
| 費目 | 重複、名前変更の反映、使用中の費目の非表示 |
| 権限 | 別ユーザーと匿名からのアクセス拒否、MCP経由のRLS |
| MCP | 不正な入力、削除、`dry_run` で書き込まれないこと |
| CSV | 再取り込み、固定費との一致、除外済み行が含まれないこと |
| PWA | iPhone Safari、ホーム画面起動、JSTの日付境界 |

バグと追加タスクは個人のJiraプロジェクトMYSTで管理する。

- 要件を変える必要が出たら、実装前に確認する
- コミットとプッシュは本人の指示があるときに行う
