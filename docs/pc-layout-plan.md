# PC版レイアウト 実装指示書

## 1. 目的
PCのブラウザで開いたときは、広い画面を活かしたPC版レイアウトを表示する。iPhoneでは今のモバイル版をそのまま表示する。

- URL、DB、MCP、APIは変更しない
- 既存の画面部品とデータ処理を使い回し、PC用の外枠と配置だけを追加する
- モバイル版の見た目と動作を変えない

## 2. 確定した仕様

### 2.1 切り替え条件
- 画面幅 `min-width: 1024px` でPC版、それ未満でモバイル版
- 端末の種類（UA）では判定しない
- 横向きで幅1024px以上のiPadはPC版を表示する
- PCでウィンドウを狭めた場合もモバイル版に切り替わる
- 切り替わっても、入力中の内容、選択中の月と日、ログイン状態を失わない

### 2.2 画面構成
| PC版の画面 | 内容 | モバイル版の対応画面 |
|---|---|---|
| ホーム | 集計、カレンダー、入力フォーム、選択日の内訳を1画面に表示 | 入力、カレンダー |
| 固定費 | 一覧表と編集フォームを左右に表示 | 固定費、固定費の登録 |
| サブスク | 一覧と編集フォームを左右に表示 | サブスク |
| 費目 | 4種類の費目を並べて編集 | 費目の編集 |

ナビは左サイドバーに置く。項目はホーム、固定費、サブスク、費目、ログアウト。PC版では下タブを出さない。

### 2.3 ホーム
見本: `docs/mock/PcHome.dc.html`

- **上部:** 月の移動、今月ボタン、集計（月の支払い、支払い済み、これから、収入、振替/投資）
- **中央:** 7列のカレンダー。各日に支払い済み、予定、収入を表示する
- **右側:** 入力フォームを常に表示し、その下に選択日の内訳を表示する
- 日付を選ぶと、内訳とフォームの日付が切り替わる
- 内訳の明細を選ぶと、右のフォームで編集できる
- 内訳の固定費を選ぶと、固定費画面の編集フォームを開く
- 登録、更新、削除の後は、集計、カレンダー、内訳をすぐ更新する
- 費目と支払方法は選択式にする
- 金額欄でEnterを押すと登録する。ただし、日本語入力の変換確定中は登録しない
- 振替/投資は月の支払いに含めず、集計の別枠と内訳に表示する（既存の計算と同じ）

### 2.4 固定費、サブスク
見本: `docs/mock/PcFixed.dc.html`

- 左に一覧表（名前、費目、支払日、支払方法、記録方法、金額）、右に編集フォームを表示する
- 行を選ぶと右で編集し、「追加」で空のフォームにする
- 一覧上部に月額合計、年額、件数を表示する
- フォームの項目と入力チェックは既存の `FixedFormScreen` と同じ
- サブスク画面は既存の `SubscriptionScreen` の内容を同じ左右配置で表示する

### 2.5 費目
- 支出、収入、振替/投資、固定費の4列を並べて表示する
- 追加、名前変更、並び替え、非表示の動作は既存と同じ

## 3. 実装方針

1. **幅の判定:** `matchMedia('(min-width: 1024px)')` を使う `useIsDesktop` フックを作る
2. **データと状態の共有:** `Shell.tsx` にある読み込み、`version`、トースト、編集対象などの状態を `useAppState` などの共通フックへ移す。モバイル版とPC版で同じ状態を使い、切り替えで状態を失わないようにする
3. **外枠の出し分け:** `App.tsx` でモバイル版の `Shell` とPC版の `DesktopShell` を出し分ける
4. **画面部品の分離:** 各画面のフォームや一覧などを、画面全体と分けて使えるようにする
   - 例: `EntryForm`、`MonthCalendar`、`DayDetail`、`FixedTable`
   - モバイル版の画面は、分けた部品を今までどおり組み合わせて表示する
5. **CSS:** PC用のスタイルを `@media (min-width: 1024px)` か専用クラスで追加する
   - `html`、`body` の `position: fixed` と `overflow: hidden`、`.app` の `max-width: 480px` は、iOSの画面揺れ対策なのでモバイル版では残す
   - PC版では、ページ全体ではなく、各列の中身をスクロールさせる
6. **見本の扱い:** 配色、余白、角丸、フォントは既存のCSS変数に合わせる。モックのサンプルデータと状態管理のコードは流用しない

## 4. 完了条件
- 幅1024px以上でPC版、1023px以下でモバイル版になる
- iPhone Safariとホーム画面起動時の見た目と動作が、変更前と同じ
- PC版で、入力、編集、削除、固定費、サブスク、費目の機能を使える
- ウィンドウ幅を変えても、入力中の内容と選択中の月日が残る
- `npm run build` と `npm test` が通る

## 5. テスト観点
| 区分 | 観点 |
|---|---|
| 切り替え | 1023pxと1024pxの境界、ウィンドウ幅の変更、iPadの縦向きと横向き |
| 状態 | 切り替え時の入力内容、編集中の明細、選択中の月日、ログイン状態 |
| ホーム | 日付選択とフォーム日付の連動、登録後の集計とカレンダーの更新、月移動 |
| キーボード | Enterでの登録、日本語変換中のEnterで登録されないこと、Tab移動の順序 |
| 固定費 | 行選択で編集、追加、削除後の一覧と合計の更新 |
| 費目 | 4列での追加、名前変更、並び替え、非表示 |
| モバイル回帰 | iPhoneでの全画面、下タブ、画面全体が引っ張られないこと |
| 表示 | 1024px、1280px、1440px、1920pxで崩れないこと |

`npm run dev:fake` で、サンプルデータを使って確認できる。

## 6. 進め方
- 3章の1〜3を先に行い、モバイル版が変わっていないことを確認してから、PC版の画面を作る
- PC版はホーム、固定費、サブスク、費目の順に作る
- 要件を変える必要が出たら、実装前に確認する
- コミットとプッシュは本人の指示があるときに行う
